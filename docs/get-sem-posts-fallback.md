# getSemPosts 条件回退补丁

状态：已并入主流程作为兜底安全网；新版帖的主解锁路径已由网页客户端身份取代（见 docs/web-client-identity.md）。

## 依据（修正后）
最初判断「官方网页成功请求实际是 getSemPosts」被后续 F12 完整抓包证伪：成功请求就是 getPostFull（gids=8&post_id=…&read=1 + 网页客户端身份头组）。设备诊断同时证明 getSemPosts 返回的是语义相关帖列表（候选均不含目标 ID），不是详情通道。
本补丁的有效部分：仅当 getPostFull 业务层明确 retcode=-1、data 为空、message 含「升级」时兜底一次；命中条件为 data.list 内 post_id 精确等于目标，否则停用不近似。截图凭据不得存档。

## 实现
- 正常getPostFull成功保持原流程；只对retcode=-1、空data、升级提示回退一次getSemPosts。HTTP错误、其它业务错误不自动切接口。
- 复用米柚自身既有请求头及会话，不复制浏览器Cookie、token或设备指纹。
- PostContext按帖子ID保存响应中的post.game_id，缺失时看forum.game_id；不依据搜索词或当前全局选择推断。只在内存保存，最多2048条。
- 搜索posts、首页fixed_posts/recommended_posts、用户主页list均接入记录；成功详情刷新映射。未知频道不扫描或猜测；没有真实game_id时保留原错误。
- 对成功详情校验返回post_id，防止错帖；楼中楼优先使用记录的真实频道而不是旧调用处固定2。
- 数组Delta包成具名Record上下文的{ops:数组}，不再被obj()丢弃；对象型{ops:[]}照旧。
- 接口诊断回执追加最近详情加载路径摘要（trace 已改追加式，中间跳不再被覆盖），不记录请求头/Cookie/响应头。诊断任意URL入口保留官方白名单。
- 不改页面布局、V5.1图片预览、版本0.8.0及搜索胶囊样式。

## 验收
1. 同词跨频道搜索后，79139530正确打开且标题、正文、作者匹配（b147 起由网页身份主路径达成，本补丁不再触发）。
2. 原神旧帖正常打开；不触发无条件双请求。
3. 新接口403、业务失败、成功但ID不匹配、未知频道均不假报成功。
4. 数组Delta、对象ops、纯describe降级、链接和视频回归。
5. 非原神楼中楼、首页入口、用户主页入口回归。
6. 若仍失败，复制诊断摘要确认实际频道和各跳回执；不能宣称浏览器实测等于App实测。
