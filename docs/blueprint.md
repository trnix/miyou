## v1.8 变更摘要

- **R4 扫码登录第一阶段实装**：链路与请求头逐行对齐仍在维护的上游开源项目 TeyvatGuide 源码（`passportReq.ts` / `GameLogin.d.ts` / `getRequestHeader.ts` / `TGBbs.ts`）——`passport-api …/app/createQRLogin`（POST `{}`）→ `…/app/queryQRLoginStatus` 轮询（Init/Created/Scanned → Confirmed；-106 二维码过期属自动刷新）；确认后 `tokens[0].token` 为 stoken，`user_info.aid`/`mid` 为账号标识；另实现 stoken→ltoken 可选换发。凭据合并写入 Session（stuid/stoken(+v2)/mid/ltuid/account_id 系列）。
- **DS 签名 salt 落地**：K2/LK2/X4/X6 取自 TeyvatGuide 公开仓库（与其配套版本线 2.115.0 绑定），`DsSign.SIGN_VERSION` 与 `Endpoints.APP_VERSION` 解耦。二维码渲染使用系统内置 `QRCode` 组件，零三方依赖。
- **历史结论纠偏**：(1) record 域 ltoken 请求返回 -10001 存在歧义（错误码表同时标注其为「Cookie 过期」类），不能作为「必须 stoken」的唯一证据，R5 设计时应分别以 Cookie 组合与 DS 签名两轮校验；(2) R3 移除成立（范围取舍），但「两个猜测 URL 404」仅证伪那两个路径，不构成「消息接口技术上不存在」的结论，v1.7 相关表述以本条为准。

## 0. 总原则

1. 蓝图对标官方：信息架构、模块边界、页面流以官方 App 为参照；实现为纯 ArkTS/ArkUI 干净重写，不使用官方任何代码、bundle 与素材。
2. 只读先行：前期不实现任何远端写入。网络层已具 DS1/DS2 签名与完整 Cookie 能力，写功能归入 R7 灰度，开启前单独风险评估与用户明示。
3. 防御性实现：接口字段缺失/变动不得导致崩溃；统一 snake_case→camelCase 映射层 + 缺省兜底。
4. 官方材质 API 启用规则：`uiMaterial.ImmersiveMaterial` 为 API 26 正式能力，允许使用；必须配能力探测与属性顺序规则（3.2.7）。
5. 资产约束：bundleName 固定 `com.miyou.app`；图标为米哈游版权素材、仅限自用不分发（见 v1.4）。
6. **接口预验原则（v1.7）**：新模块动工前必须先以最低成本验证数据接口可达或拿到可追溯的上游实作源码（浏览器登录态直测 / 读取仍在维护的开源实现均可算数）。拿不到证据不排进迭代。
7. **上游证据优先（v1.8）**：接口行为存疑时，以可定位到具体文件的上游开源实现为准（本项目已核验 TeyvatGuide）；只引用结论不贴出处的二手文档不得作为实现依据。

## 3. 视觉与交互规范：沉浸光感玻璃

### 3.1 开关映射（设置页「沉浸光感」）

| 状态 | 视觉效果 | 技术参数 |
|---|---|---|
| 关闭 | 纯色不透明 | REGULAR + interactive=false + 不透明 #FFF7F8FA 遮罩 |
| 开启（默认） | 厚重光感 | THICK + interactive=true + lightEffect(White) + 0.5vp 半透明白边 |

### 3.2 实现要点（实测结论持续累积）

1. `setWindowLayoutFullScreen(true)`；底部安全区须同时查 `TYPE_SYSTEM` 与 `TYPE_NAVIGATION_INDICATOR` 取最大值，监听 `avoidAreaChange` 并在 onWindowStageDestroy 释放。
2. 沉浸结构为三层叠加：底色 → 全屏内容层 → 顶部覆盖层；非首页用顶端 padding 避让，首页用 List contentStartOffset/EndOffset 做首尾避让。
3. 全屏透明覆盖容器必须 `hitTestBehavior(HitTestMode.None)`。
4. 系统栏透明 + 深色内容色。
5. 光感开关 AppStorage + preferences 持久化（glassLevel 0/3），StorageLink 联动即时生效。
6. 底栏悬浮圆角胶囊（margin 16、padding 8、圆角 32、shadow、描边）。
7. **属性顺序**：`backgroundColor` 必须写在 `systemMaterial` 之前，违者磨砂被整段覆盖。

## 4. 技术底座需求（含实证）

- 包名 `com.miyou.app`；目标 API 26。
- 网络层：x-rpc 基线（`app_version=2.117.0`、client_type=5、verify_key、UA 含 Hyperion）；扫码/签名链路使用独立版本线 `DsSign.SIGN_VERSION=2.115.0`（与 salt 配套，v1.8）。
- Cookie（实证）：v2 键为主体；多域拼接按键去重、丢空值；uid 取自 ltuid_v2/account_id_v2（扫码后 stuid 同样可用）。
- 认证等级（v1.8 纠偏）：bbs 读接口 ltoken Cookie 即可；record 域历史一次实测 -10001 存在歧义，R5 开工时按「Cookie 组合」与「DS 签名」双轮核对，不得预设 stoken 为唯一前提。
- 设备身份：device_id 首启生成持久化；device_fp 经 getFp 在线获取并持久化；device_name/model 目前为通用占位值。
- 签名：DS1/DS2 已实装并填入社区 salt（v1.8）；DS2 随机数为 100000–200000 六位数字与上游一致。
- 错误处理：-100/-10001 跳登录；1034/限流指数退避；扫码 -106 为二维码过期，自动刷新。
- 渲染：未知块/缺字段降级；`post.content` 可能为 HTML，须有兜底解析。
- 消息接口（v1.7）：不投入抓包取证。

## 6. 风险与边界

- 接口时效：渲染层兜底 + 版本/salt 集中配置化是生命线；salt 变更时以仍在维护的上游为参照对齐。
- 接口可达性前置验证（v1.7）：公开社区无文档的接口先做零成本预验，预验不过即移出排期。
- 账号风控：device_fp/device_id 成对稳定；触发 gt4 走 Web 兜底。扫码登录属官方支持流程，风控低于账密方式。
- 合规：非官方、仅查看授权数据、不接触账密；Cookie 仅存本机；图标为米哈游版权素材、仅限自用不分发。
- 签名资产：7 个 Actions 变量为唯一签名链路来源，任何重构不得输出其明文。
