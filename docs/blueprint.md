## v1.10 变更摘要

- **扫码问题归因修正**：v1.9 记「扫码被 retcode -10001 拒绝」是错的——真机反馈澄清 -10001 来自探活的 record 战绩域（扫码闭环未走完，凭据槽照旧，这属预期）；扫码页本身的表现是「二维码能生成、官方 App 能识别，扫码确认后米柚轮询状态一直不变」。b84（TeyvatGuide 头组：bll8iq97cem8 + miHoYoBBS/2.115.0）官方 App 侧显示「米游社 PC 登录」，b85（dsh 头组：ddxf5dufpuyo + HYPContainer）显示「米哈游启动器登录」——证明两条通道的二维码签发生成都正常，问题集中在查询环节的状态解析或响应结构。
- **R4.1 诊断构建**：MysHttp 增设响应头文本透传（供 Set-Cookie 解析；界面不得展示）；查询环节每轮产出结构级诊断（HTTP 码/retcode/message 截断/status 原值/data 顶层键名，不含 token）；确认态凭据来源从「仅 tokens 数组」扩为 tokens + Set-Cookie 双路；hasToken 闸门要求至少一个真 token（身份字段不算）；页面请求批次号防旧响应竞态；扫码成功后整体替换会话（不与旧 Cookie 合并，防跨账号残留）。
- **米悠社 1.1.8 报告定位**：作为调查线索使用，不作为实现依据。报告中「指纹异常被拒」「DS2 已升级 HMAC-SHA256」「客户端实现了消息中心」均未获反汇编证实（未定位调用点、未提取常量明文、未做动态观测），此前据此得出的结论已撤回。唯一可直接采纳的是它证明了 2.109.0 版本线 + miyousheluodi channel + 防御性多签算法集是一个运行中的客户端的选型。

## 0. 总原则

1. 蓝图对标官方，实现为纯 ArkTS/ArkUI 干净重写，不使用官方任何代码、bundle 与素材。
2. 只读先行：前期不实现任何远端写入。写功能归 R7 灰度。
3. 防御性实现：接口字段缺失/变动不得导致崩溃。
4. 官方材质 API 启用规则：`uiMaterial.ImmersiveMaterial` 允许使用，必须配能力探测与属性顺序规则。
5. 资产约束：bundleName 固定 `com.miyou.app`；图标为米哈游版权素材、仅限自用不分发。
6. **接口预验原则（v1.7）**：新模块动工前必须以最低成本验证接口可达或拿到可追溯的上游实作源码。
7. **上游证据优先（v1.8–v1.10）**：以可定位具体文件的上游源码为准；多上游以仍在维护者优先；**静态逆向报告只作线索，不作为实现依据**（v1.10 增补）。
8. **诊断先行（v1.10）**：涉及风控/签名的接口出错时，先让错误自报家门（返回结构键名与原值），再改请求参数；盲改头组两轮仍无进展，即走诊断构建路线。

## 3. 视觉与交互规范：沉浸光感玻璃

| 状态 | 视觉效果 | 技术参数 |
|---|---|---|
| 关闭 | 纯色不透明 | REGULAR + interactive=false + 不透明遮罩 |
| 开启（默认） | 厚重光感 | THICK + interactive=true + lightEffect(White) + 0.5vp 半透明白边 |

实现要点：全屏 + 双类型安全区取最大值 + avoidAreaChange；三层叠加（底色/内容层/顶部覆盖层）；覆盖容器 `hitTestBehavior(None)`；AppStorage + preferences 持久化（glassLevel 0/3）；悬浮胶囊底栏（margin 16、padding 8、圆角 32、shadow、描边）；`backgroundColor` 必须写在 `systemMaterial` 之前。卡片结构拆解见 v1.2–v1.5 git 历史。

## 4. 技术底座需求（含实证）

- 包名 `com.miyou.app`；目标 API 26。
- 网络层版本线三条并存：`Endpoints.APP_VERSION=2.117.0`（读接口）；`QrLoginApi` 2.109.0（扫码上游配套）；`DsSign.SIGN_VERSION=2.115.0`（DS salt 配套）。三者不可混用。
- Cookie（实证）：v2 键为主体；扫码后凭据整体替换（v1.10），身份别名由 user_info.aid/mid 补全。
- 认证等级：bbs 读接口 ltoken Cookie 即可；record 域认证需求待 R5 双轮核验。
- 设备身份：device_id 首启生成持久化；通行证扫码链路不发 device_fp（v1.9 上游实证）。
- 签名：DS1/DS2 MD5 路线已实装；**DS2 是否已升级 HMAC-SHA256 未证实**（v1.10：该说法源自米悠社报告的推断段，未获反汇编明文证实，R5 先走 MD5 路线试，失败再调整）。
- 错误处理：-100/-10001 跳登录；1034 限流退避；扫码 -3501/-3505/-106 过期自动刷新。
- 渲染：未知块降级；post.content 可能为 HTML。
- 消息接口：不投入抓包取证（v1.7）。

## 6. 风险与边界

- 接口时效：渲染层兜底 + 版本/salt 集中配置化。
- 接口可达性前置验证（v1.7）。
- 上游时效差（v1.9）：仍在维护、近期发布者优先。
- 静态逆向报告边界（v1.10）：反汇编未定位调用点/未提取常量明文的结论一律按线索处理，不进实现依据。
- 账号风控：device_fp/device_id 成对稳定；触发 gt4 走 Web 兜底。
- 合规：非官方、仅查看授权数据、不接触账密；Cookie 仅存本机；图标为米哈游版权素材、仅限自用不分发。
- 签名资产：7 个 Actions 变量为唯一签名链路来源，任何重构不得输出其明文。
